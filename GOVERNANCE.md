# Governance

Clean Development currently uses a maintainer-led model. Magrathean UK is the initial maintainer and has final responsibility for merges, releases, security responses, and the project name.

Most decisions happen in issues and pull requests. Changes to deletion behavior, ownership rules, configuration compatibility, licensing, or the stable CLI should be discussed publicly before merge, except when private handling is required for security.

Regular contributors may be invited as maintainers after sustained, constructive work and sound judgment around destructive operations. Maintainers disclose relevant conflicts and avoid reviewing their own security-sensitive release changes when another maintainer is available.

If the initial maintainer becomes inactive, established maintainers should first try private contact, then document a succession proposal publicly. The MIT license always permits a fork; no contributor is promised control of the original npm or GitHub namespace.
