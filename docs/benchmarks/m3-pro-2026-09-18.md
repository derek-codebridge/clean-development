The current safety-hardened path is not consistently below the provisional `0.1.x` p95 ceiling of 75 ms: the latest four runs ranged from 75.96 ms to 97.73 ms, and prior runs reached 145.14 ms. The gate is therefore not met under observed variance, and the path does not meet the 50 ms optimization target. Release benchmarking should run on supported Node 20, 22, and 24, include cold starts and system-load variance, and measure real short and long build commands.

The benchmark targets dispatch overhead, not build acceleration. For a multi-second build, cache reuse and avoided redownloads should dominate this cost; that still needs separate cold/warm measurements.
